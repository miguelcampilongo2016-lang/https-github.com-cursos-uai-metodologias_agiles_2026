## Enunciado:
1) ¿Qué es Extreme Programming (XP) y cúal es su objetivo principal dentro de las metodologías?
2) ¿Cúales son los cinco valores principales de XP? Explica brevemente cada uno
3) ¿Por qué XP considera que las pruebas son un elemento fundamental del desarrollo de software?
4) ¿Que es el Test Driven Development (TDD) y como se relaciona con XP?
5) ¿En qué consiste la práctica de Pair Programming? Mencioná dos ventajas y una posible dificultad
6) ¿Qué son las historias de usuario en XP y porque se prefieren frente a una especificación extensa de requisitos?
7) ¿Qué significa Continous Integration en XP y que beneficios aporta al equipo de desarrollo?
8) ¿Cómo se aplica el concepto de Weekly Cycle en un proyecto de desarrollo con XP?
9) En XP se plantea que se fija el tiempo, el costo y la calidad, y se negocia el alcance.¿Qué significa esta idea? Explicalo con un ejemplo
10) Elegí tres prácticas de XP y explica cómo podrían aplicarse en un proyecto real de desarrollo de software  

## Resolución:

1) El XP es una metodología ágil enfocada en la práctica de la programación, su objetivo principal es tratar de responder rápidamente al cambio, evitar
   los errores, generar un buen ambiente de trabajo y tener una colaboración constante con el cliente, a la par de una entrega constante de valor
2) Los cinco valores de XP son;
1. Comunicación; Conversación constante con el equipo y con el cliente
2. Simplicidad: Cumplir con lo necesario
3. Retroalimentación: Obtener retroalimentación constante 
4. Valentía; animarse a cambiar el código en caso de ser necesario y mejorar
5. Respeto: respetar y confiar en el equipo, con sinceridad, al igual que con el cliente. 
3) XP considera que las pruebas son el elemento fundamental del desarrollo de software debido a que mediante ella se puede lograr entender las
   funcionalidades, mejorarlas y corregirlas sin miedo. Mediante el uso de TDD logran poder hacerlo. 
4) El Test Driven Development es una de las herramientas que tiene XP, para muchos es la herramienta más importante, consiste en una metodología de
    trabajo de tres pasos: Red, Green y Blue. La premisa es que a partir de un CU se haga una prueba de una funcionalidad que falle, de forma intencional,
     posteriormente se corrige como se pueda para que esta de un valor correcto, es decir para que funcione y posteriormente se perfecciona para que
     funcione sin problemas y de forma limpia. 
5) El Par Programming es otra herramienta de XP, una de las mejores que tiene, se basa en la premisa de programar en parejas. ¿Que ventaja tiene esto?
     Siendo dos personas en una misma computadora, trabajando con el mismo código se vuelve más liviano el trabajo, ambos pueden charlar y debatir sobre
     el código sus complicaciones y posibles soluciones, siendo también un espacio propicio para el aprendizaje.
	Ventajas:
		- Se tiene una doble confirmación los códigos.
		- El trabajar en grupos de a dos, y que se roten, ayuda a que el equipo se conozca y genere confianza y un buen entorno de trabajo
	Desventajas:
		- Teniendo dos personas haciendo un trabajo, aumenta la calidad, pero puede ser menos eficiente que una forma de trabajo mas tradicional.
6) Las historias de usuario en XP se piensan como historias cortas, de pocos renglones, que cumplan las condiciones de INVEST, estas suelen ser de un pequeño
    párrafo y con una estimación de tiempo. Se ven de esta forma porque si se piensan como “requerimientos” se pueden ver como “inmutables”
7) Continuous Integration es una práctica de XP basada en integrar cambios pequeños y frecuentes al código principal del proyecto. Su objetivo es detectar
   errores tempranamente, evitar conflictos entre versiones y mantener un desarrollo estable y continuo.
8)  Wekly Cycle es otra práctica de XP, esta se basa en tratar de organizar y planificar el cronograma de la semana del equipo. El primer día de la semana
    se piensa que sucedió la semana anterior, que se puede mejorar y que se podría implementar. También en este momento se suelen tomar las nuevas historias
    de usuario para realizar la codificación y se suele pretender que se cumplan dentro de dicha semana.
9) XP considera que el tiempo y el costo son fijos, dado que la calidad del software no es negociable. El alcance es la variable de negociación, por lo que
   lo que se entrega al cliente se ajusta según el tiempo disponible, asegurando siempre software funcional y de calidad.
Ej: Un equipo XP trabaja con una empresa que solicita un sistema web de control interno, contabilidad y atención al cliente. Se acuerda un presupuesto y
un plazo fijo, y el desarrollo se organiza en iteraciones cortas. Durante el desarrollo, se detecta que el alcance original es demasiado grande para el
tiempo disponible. En lugar de extender el plazo o aumentar el costo, el equipo y el cliente re-priorizan las historias de usuario. Se decide entregar
primero un sistema de control interno básico que permita gestionar mercadería y operaciones contables esenciales. Las funcionalidades de interacción con
clientes se dejan fuera del incremento actual, pero quedan priorizadas para futuras iteraciones. De este modo, se garantiza la entrega continua de software
 funcional, ajustando el alcance sin comprometer la calidad.

10) Prácticas de XP:
	Informative Workspace (Espacio de trabajo informativo):
Consiste en mantener información visible sobre el estado del proyecto (por ejemplo, mediante tableros físicos o digitales con tareas, progreso y bloqueos).
Esto permite que todo el equipo tenga una visión clara del avance y del trabajo pendiente en todo momento, facilitando la coordinación.
	Sit Together (Trabajar juntos):
Propone que el equipo de desarrollo comparta el mismo espacio físico o un entorno de trabajo cercano. Esto favorece la comunicación directa,
reduce malentendidos y mejora la colaboración entre los miembros del equipo. 	
	Pair Programming (Programación en pareja):
Consiste en que dos desarrolladores trabajen juntos en una misma tarea: uno escribe el código mientras el otro revisa y sugiere mejoras en tiempo real.
 Esto mejora la calidad del código, reduce errores y favorece el aprendizaje, especialmente en equipos con desarrolladores junior.
